# water-koubo

把一篇完整参考稿改成沿用原主题、可以直接拍摄的简体中文口播稿。实际使用只需要参考稿；方法选择和检查由本 Skill 完成。

## 识别当前请求

按以下顺序处理：

1. 用户提供了完整参考稿时，进入“直接出稿”。
2. 参考稿缺失、内容残缺或附件无法完整读取时，进入“缺少参考稿”。

不要让用户选择模式，不要求填写身份、经历、案例或写作偏好。当前对话中已经主动提供的信息可以直接使用。

## 直接出稿

- 一次只使用一篇完整参考稿。
- 支持直接粘贴文本，以及宿主能够完整读取的 TXT、Markdown、Word 和可选中文本 PDF。
- 不自行抓取网页、下载视频、转录音频或识别扫描图片。
- 正常成稿始终使用简体中文。
- 读到完整参考稿后立即开始；不回复“收到”，不显示进度，不解释准备怎样处理。
- 按顺序执行 `[M01]` 至 `[M10]`，再完成 `[Q01]` 至 `[Q06]`。
- 当前对话中明确提出的表达要求只用于本次成稿，参考稿的事实边界优先。

## [M01] 锁定单一完整来源

只使用当前这一篇完整参考稿，不拼接其他稿件，不自行联网补料，也不把参考稿自动视为已经过数据验证。

先确认参考稿的主题、核心结论、受众、信息范围和大致体量。用户给出时长、字数或发布场景时按当前要求执行；没有给出时，跟随参考稿的篇幅和信息密度。

## [M02] 拆出六项写作作用

按原文顺序识别每一段承担的作用：

1. **核心判断与限定**：原稿要证明什么，在哪些条件下成立，排除了什么误解。
2. **因果推进**：问题、原因、结果、转折和升级怎样连接。
3. **开头功能**：开头靠冲突、结果、悬念、反常识或受众筛选中的哪些作用留人。
4. **案例证明**：案例具体证明哪一层判断，哪些细节让证明成立。
5. **爆点位置**：最强认知变化或情绪释放出现在哪里，前文怎样把它推到那里。
6. **结尾意义**：观众最后带走什么判断、行动或认同，它怎样回应开头。

不能只摘关键词或概括主题。必须知道每段在做什么，以及为什么出现在当前位置。

## [M03] 保留原段落顺序和推进关系

为原稿每一段安排明确去向，保留原段落顺序和推进功能。长段可以拆成适合口播的短段，但不得提前后面的爆点、移动案例原本的证明位置、合并必要的推进步骤，或把结尾换成无关的点赞关注口号。

发生冲突时，按以下优先级取舍：核心判断与成立条件 → 因果推进与段落顺序 → 案例的证明作用 → 开头、爆点和结尾的位置作用 → 情绪强度与篇幅 → 表面措辞。

## [M04] 按段落作用重写具体内容

根据每一段的作用选择改写方式：

- 原段落提供判断、原则或方法时，写出新的具体判断，保留它在论证中的位置。
- 原段落靠步骤、动作或前后变化成立时，保留流程关系和证明链，重写具体动作与表达。
- 原段落靠第一人称材料成立时，先按 `[M05]` 处理归属，再恢复它的证明作用。

避免连续沿用原句的句法、比喻和标志性表达。改动具体表达不能破坏原稿成立的原因。

## [M05] 处理第一人称和案例归属

参考稿里的第一人称经历、客户、收入、作品、数据和结果，不得写成使用者亲历。

当前对话中已有用户明确授权使用的等价事实时，可以替换，并保留原案例的证明作用。没有等价事实时，改成外部案例或普通场景，保留对象、关键动作、变化和结果关系；删除无法确认的具体成绩，不向用户索要替代案例。

示例：参考稿写“我服务过一家店”，没有用户授权素材时，可以写成“常见的一种情况是，一家店每天发内容，却没人说得清顾客为什么要来”。

## [M06] 在前 3 段加入一个新增判断

新稿需要在正文前 3 段加入一个新增判断。它可以补充成立条件、指出被忽略的原因、说明新的后果，或把原案例提升成更明确的结论。

新增判断必须接在现有因果推进上，不能另起一篇，不能冒充原作者原话，也不能依赖虚构经历。它要帮助观众更快理解这篇稿为什么值得继续听。

## [M07] 保住案例证明密度

尽量维持参考稿的案例数量、出现位置和证明强度。替换案例时，至少保留原案例中负责证明判断的对象、关键动作、过程变化和结果关系。

不要为了扩大文字差异而删掉关键证据，也不要把具体案例改成空泛口号。无法保留具体数字时，用可确认的过程关系承担证明，不编造新数字。

## [M08] 校准开头、爆点和结尾

- 开头保留原稿的开头功能组合，重新写具体句子。
- 爆点保持在原稿对应的相对位置，让前文继续为它积累信息和情绪。
- 结尾保留原稿最后一层意义并回应开头，不额外添加与正文无关的行动口号。

标题和封面文字从正文最强判断中提取，不能添加正文没有兑现的承诺。

## [M09] 校准事实、术语和口语表达

保持术语关系、数字含义和事实归属准确。无法确认归属的结果不能改写成确定事实；参考稿本身没有提供的机制、数据、时间或成绩不能自行补充。

保持原稿的情绪强度和转折力度，同时把书面解释改成自然口语。删除重复铺垫和空泛总结，让每一段都能顺口说出。用户当前明确的表达要求只作用于本次成稿。

## [M10] 生成一份一致的交付结果

只生成一个标题、一条封面文字和一篇口播正文。三者使用同一个核心判断，正文按自然口播段落排版，不加“开头”“案例”“爆点”“结尾”等标签。

不展示方法分析、检查记录或修改过程。不附加发布建议、风险说明、模型信息或额外结语。

## [Q01] 六项作用完整

初稿完成后最多 5 轮检查。问题已经解决就立即停止，不为了凑轮数继续改写。

确认核心判断与限定、因果推进、开头功能、案例证明、爆点位置和结尾意义都有明确对应内容。

## [Q02] 顺序和位置正确

确认原段落顺序、案例位置、爆点相对位置和结尾回应关系没有被改坏。

## [Q03] 新增判断有效

确认新增判断出现在前 3 段，接在原有因果链上，并且没有依赖无来源事实。

## [Q04] 案例与第一人称归属正确

确认案例证明密度足够，第一人称、客户、收入、数据和结果没有被错误转给使用者。

## [Q05] 事实和语言准确

确认术语、数字、事实归属、情绪强度和简体中文口语表达准确自然。

## [Q06] 三项结果一致

确认标题、封面文字和正文来自同一个最强判断，没有夸大，也没有出现三个字段之外的内容。

## 直接交付

只输出：

```text
标题：

封面文字：

口播正文：
```

第一行必须是“标题：”。只交付一份结果，不添加前言、方法说明、评分、检查过程、模型名称、发布建议、风险说明或额外结语。

## 缺少参考稿

只回复这一句话：

`把完整参考稿发我。`

不要同时索要其他资料。

## 固定边界

- 不联网，不调用外部服务器，不索取 API Key，不发送遥测，不自动更新。
- 不承诺播放量、转化或必然成为爆款。
- 参考稿中的第一人称经历、客户、收入、数据和结果，不得自动写成使用者亲历。
- 不编造用户身份、客户、收入、成绩、数据来源或项目结果。
