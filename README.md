## water-koubo 解决什么问题

创作者手里有一篇值得参考的完整口播稿时，water-koubo 会保住它真正有效的部分，再完成一篇表达不同、归属准确、能够直接拍摄的新稿。

| 你的情况 | water-koubo 交付的结果 |
|---|---|
| 想保住参考稿的核心内容 | 主题、核心判断和必要限定保持准确 |
| 原稿依靠顺序和递进关系成立 | 结构、段落作用和爆点位置得到保留 |
| 原稿带有第一人称经历或案例 | 经历属于谁、案例证明什么都会重新校准 |
| 希望成稿有自己的信息 | 正文前段加入一个能够成立的新判断 |
| 需要直接进入拍摄 | 一次交付标题、封面文字和简体中文口播正文 |

## 快速开始

安装完成后，在支持 Skills 的 Agent 中输入：

~~~text
$water-koubo
【粘贴或附上一篇完整参考稿】
帮我二创成一篇可拍口播稿。
~~~

参考稿完整可读时，water-koubo 会直接交付成稿。

## 能力一览

| 能力 | 用户得到的结果 |
|---|---|
| **核心判断保真** | 抓住参考稿真正想说的内容，二创后主题不跑偏 |
| **结构与顺序保真** | 留住原稿的递进关系、段落作用和爆点位置 |
| **开头重新创作** | 保留开头承担的作用，换成新的进入方式 |
| **案例与归属校准** | 保留案例的证明力，讲清经历和成绩属于谁 |
| **新判断与爆点推进** | 补入一个能成立的新判断，让成稿增加有效信息 |
| **结尾与三项结果统一** | 让标题、封面文字和口播正文说的是同一件事 |

六项能力共同遵守三个成稿标准：顺口、可拍、事实准确。

## 安装

在终端执行：

~~~bash
npx -y skills add waterbrojx/water-koubo -g --all
~~~

安装后回到支持 Skills 的 Agent，使用 **$water-koubo** 加一篇完整参考稿即可开始。ZIP 导入时选择 **skills/water-koubo** 目录。

## 怎样工作

~~~text
一篇完整参考稿
      ↓
看懂这篇稿为什么成立
      ↓
保住有效结构、案例和爆点
      ↓
重新写判断、句子和细节
      ↓
校准事实与经历归属
      ↓
标题＋封面文字＋可拍正文
~~~

1. 读取完整参考稿和当前要求。
2. 找出核心判断、推进顺序、开头、案例、爆点和结尾分别承担的作用。
3. 保留这些作用，重写判断、句子和细节，并加入一个能成立的新判断。
4. 按照当前对话中明确提出的表达要求调整本次成稿。
5. 只交付标题、封面文字和口播正文。

## 公开方法库

完整中文方法公开在 [method.md](skills/water-koubo/references/method.md)，覆盖四个部分：

- 识别参考稿的核心判断、顺序、开头、案例、爆点和结尾；
- 保留有效机制，重新写具体判断、句子和细节；
- 处理第一人称、案例归属、事实和术语；
- 检查新增判断、证明密度和三项结果是否一致。

所有人都可以查看、下载这份方法，也可以 Fork 项目后在自己的版本中修改。Fork 中的修改只作用于 Fork 后的版本，官方版本由老肖AI运营维护。

方法库使用短小虚构例子说明案例归属，不收录私人稿件、客户资料或无法公开的来源材料。

## 完整使用说明

### 输入

- 每次提供一篇完整参考稿；
- 支持直接粘贴文本，以及宿主能够完整读取的 TXT、Markdown、Word 和可选中文本 PDF；
- 无法完整读取时，只会要求补充完整参考稿。

### 语言

- 项目介绍提供简体中文、繁體中文和 English 三个版本；
- 三套 README 介绍同一个中文 Skill；
- 正常成稿使用简体中文。

### 输出

输出固定为：

~~~text
标题：

封面文字：

口播正文：
~~~

正常结果不附加过程说明、评分或发布建议。

### 必要限制

- 一次只处理一份完整参考稿；
- 不负责抓取网页、下载视频、转录音频或识别扫描图片；
- Skill 本体不联网、不索取 API Key、不发送遥测，也不会自动更新；
- 宿主工具和所选模型怎样处理数据，以它们各自的设置与条款为准。
