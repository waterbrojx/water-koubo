## water-koubo 解決什麼問題

創作者手上有一篇值得參考的完整口播稿時，water-koubo 會保住它真正有效的部分，再完成一篇表達不同、歸屬準確、能夠直接拍攝的新稿。

| 你的情況 | water-koubo 交付的結果 |
|---|---|
| 想保住參考稿的核心內容 | 主題、核心判斷和必要限定保持準確 |
| 原稿依靠順序和遞進關係成立 | 結構、段落作用和爆點位置得到保留 |
| 原稿帶有第一人稱經歷或案例 | 經歷屬於誰、案例證明什麼都會重新校準 |
| 希望成稿有自己的資訊 | 正文前段加入一個能夠成立的新判斷 |
| 需要直接進入拍攝 | 一次交付標題、封面文字和簡體中文口播正文 |

## 快速開始

安裝完成後，在支援 Skills 的 Agent 中輸入：

~~~text
$water-koubo
【貼上或附上一份完整中文參考稿】
幫我二創成一篇可拍的中文口播稿。
~~~

參考稿完整可讀時，water-koubo 會直接交付成稿。

## 能力一覽

| 能力 | 使用者得到的結果 |
|---|---|
| **核心判斷保真** | 抓住參考稿真正想說的內容，二創後主題不跑偏 |
| **結構與順序保真** | 留住原稿的遞進關係、段落作用和爆點位置 |
| **開頭重新創作** | 保留開頭承擔的作用，換成新的進入方式 |
| **案例與歸屬校準** | 保留案例的證明力，說清楚經歷和成績屬於誰 |
| **新判斷與爆點推進** | 補入一個能成立的新判斷，讓成稿增加有效資訊 |
| **結尾與三項結果統一** | 讓標題、封面文字和口播正文說的是同一件事 |

六項能力共同遵守三個成稿標準：順口、可拍、事實準確。

## 安裝

在終端執行：

~~~bash
npx -y skills add waterbrojx/water-koubo -g --all
~~~

安裝後回到支援 Skills 的 Agent，使用 **$water-koubo** 加一篇完整參考稿即可開始。ZIP 匯入時選擇 **skills/water-koubo** 目錄。

## 怎樣運作

~~~text
一篇完整參考稿
      ↓
看懂這篇稿為什麼成立
      ↓
保住有效結構、案例和爆點
      ↓
重新寫判斷、句子和細節
      ↓
校準事實與經歷歸屬
      ↓
標題＋封面文字＋可拍正文
~~~

1. 讀取完整參考稿和目前要求。
2. 找出核心判斷、推進順序、開頭、案例、爆點和結尾分別承擔的作用。
3. 保留這些作用，重寫判斷、句子和細節，並加入一個能成立的新判斷。
4. 按照目前對話中明確提出的表達要求調整本次成稿。
5. 只交付標題、封面文字和口播正文。

## 公開方法庫

完整中文方法公開在 [method.md](skills/water-koubo/references/method.md)，涵蓋四個部分：

- 識別參考稿的核心判斷、順序、開頭、案例、爆點和結尾；
- 保留有效機制，重新寫具體判斷、句子和細節；
- 處理第一人稱、案例歸屬、事實和術語；
- 檢查新增判斷、證明密度和三項結果是否一致。

所有人都可以查看、下載這份方法，也可以 Fork 專案後在自己的版本中修改。Fork 中的修改只作用於 Fork 後的版本，官方版本由老肖AI运营維護。

方法庫使用短小虛構例子說明案例歸屬，不收錄私人稿件、客戶資料或無法公開的來源材料。

## 完整使用說明

### 輸入

- 每次提供一篇完整參考稿；
- 支援直接貼上文字，以及宿主能夠完整讀取的 TXT、Markdown、Word 和可選取文字的 PDF；
- 無法完整讀取時，只會要求補充完整參考稿。

### 語言

- 專案介紹提供簡體中文、繁體中文和 English 三個版本；
- 三套 README 介紹同一個中文 Skill；
- 正常成稿使用簡體中文。

### 輸出

輸出固定為：

~~~text
标题：

封面文字：

口播正文：
~~~

正常結果不附加處理說明、評分或發布建議。

### 必要限制

- 一次只處理一份完整參考稿；
- 不負責擷取網頁、下載影片、轉錄音訊或辨識掃描圖片；
- Skill 本體不連網、不索取 API Key、不傳送遙測，也不會自動更新；
- 宿主工具和所選模型如何處理資料，以它們各自的設定與條款為準。
